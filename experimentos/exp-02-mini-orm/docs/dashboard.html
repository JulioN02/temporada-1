2Explicación general

Un ORM (Object-Relational Mapping) traduce entre dos mundos incompatibles: las filas y columnas de una base de datos relacional y los objetos tipados de un lenguaje de programación. Este Mini ORM hace esa traducción en tres mecánicas:

① Mapping
El descriptor declara tabla, columnas y tipos (int · float · string · bool · date). Es la única fuente de verdad: sin él no hay SQL.
② Query generation
Cada llamada (find, create, update…) genera SQL + bindings con ? — los valores nunca se interpolan.
③ Hydration
Las filas crudas (de node:sqlite, con null prototype) se copian a instancias reales de clase con tipos JS: 0/1 → boolean, ISO string → Date.

Las 2 gotchas de node:sqlite que el ORM resuelve

  • Booleans rechazados como binds: node:sqlite no acepta true/false como parámetro → la capa de coerción convierte bool a 0/1 antes de enlazar.
  • Filas con null prototype: las filas devueltas vienen con Object.create(null) (sin hasOwnProperty ni toString) → la hidratación copia cada columna a una instancia real de clase.

Axiomas ejercitados

  • Axioma 2 — Inyección SQL imposible: los valores solo viajan por bindings ?, nunca interpolados en el string SQL.
  • Axioma 3 — La BD decide la semántica SQL: el ORM solo emite SQL; el motor (node:sqlite) interpreta, valida y ejecuta.
  • Axioma 4 — El descriptor es la fuente única de verdad: columnas y tipos se derivan exclusivamente de él; columnas desconocidas se rechazan (assertKnownColumn).
  • Axioma 5 — API deliberadamente pequeña: 5 métodos estáticos + 2 de instancia. Nada más.
  • Axioma 8 — Conexión síncrona única: una sola conexión node:sqlite síncrona compartida por el modelo.

Cómo fluye una consulta

  1. Se llama, por ejemplo, User.find({ where: { age: 21, active: true }, orderBy: 'name', limit: 5 }).
  2. createModel(descriptor, db) ya unió descriptor + conexión en la clase User.
  3. query-builder.buildSelect produce SELECT * FROM users WHERE age = ? AND active = ? ORDER BY name LIMIT ?.
  4. coercion.toSql convierte true → 1 y las fechas → ISO antes de armar los bindings [21, 1, 5].
  5. Se ejecuta db.prepare(sql).all(...bindings) sobre la única conexión síncrona.
  6. Las filas llegan con null prototype; hydrate copia cada columna y aplica fromSql (1 → true, ISO → Date).
  7. El resultado son instancias reales de la clase User, no objetos crudos.

Semántica de save()

  • save() genera un UPDATE … WHERE id = ? con el id como último binding.
  • Sin primary key lanza un error (throw) — nunca inserta ni hace upsert.
  • Cada consulta devuelve instancias frescas: no existe identity map.
